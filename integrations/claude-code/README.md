# Мост Claude Code → SwarmViz

Claude Code ничего не сообщает SwarmViz о себе, поэтому его правки видит только
watcher — и приписывает их агенту `external`. Карта агентов при этом остаётся
пустой. Этот мост вешается на хуки Claude Code и выполняет контракт
claim-then-diff: регистрирует сессию как агента и столбит файл **до** записи,
так что diff достаётся именно ей.

## Что появляется в интерфейсе

| Виджет | Что показывает |
|---|---|
| 1 — Subagent Map | сессия как `orchestrator`, каждый вызов `Task` — дочерний `worker` со связью `TASK_DELEGATION` |
| 2 — Live Edit Stream | правки с атрибуцией `claimed` и именем агента вместо `external` |
| 3 — File Tree | счётчики правок по файлам (работало и без моста) |
| 4 — LOC Chart | дельты строк (работало и без моста) |

## Установка

1. Запусти SwarmViz на нужном репозитории с увеличенным TTL claim:

   ```bash
   ./swarmviz --path /путь/к/репозиторию --port 8942 --claim-ttl 10s
   ```

   Дефолтные `2s` брать не стоит: claim ставится в `PreToolUse`, а diff
   считается уже после дебаунса (`--interval`, по умолчанию 300 мс), причём
   запись большого файла может занять заметное время. Протухший claim = правка
   уедет в `external`.

2. Скопируй блок `hooks` из `settings.example.json` в свой
   `~/.claude/settings.json` (или `.claude/settings.json` проекта), поправив
   путь к `swarmviz_hook.py` и значение `SWARMVIZ_REPO`.

   `SWARMVIZ_REPO` в командах хуков задан не просто так. `~/.claude/settings.json`
   действует на **все** проекты, а один инстанс SwarmViz следит ровно за одним
   репозиторием: без этой переменной каждая сессия на машине заводила бы агента,
   к которому визуализатор никогда не привяжет ни одной правки. Когда она
   задана, хуки в сессиях из других репозиториев молча ничего не делают.

3. Перезапусти Claude Code — хуки читаются при старте сессии.

Проверить, что мост жив:

```bash
echo '{"session_id":"test1234","cwd":"'$PWD'"}' \
  | SWARMVIZ_DEBUG=1 SWARMVIZ_URL=http://127.0.0.1:8942 \
    python3 swarmviz_hook.py session-start
curl -s localhost:8942/api/state | python3 -m json.tool | head -20
```

В `agents` должен появиться `claude-test1234`.

## Настройки

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `SWARMVIZ_URL` | `http://127.0.0.1:8942` | база API |
| `SWARMVIZ_TOKEN` | — | bearer-токен, если сервер поднят с `--api-token` |
| `SWARMVIZ_REPO` | git-корень от `cwd` сессии | наблюдаемый репозиторий. Заодно работает как ограничитель области: если сессия запущена в другом репозитории, хуки не делают ничего |
| `SWARMVIZ_DEBUG` | — | `1` — диагностика в stderr |

## Как устроено

| Хук | Действие |
|---|---|
| `SessionStart` | `POST /api/agents` — сессия как `orchestrator`, статус `RUNNING` |
| `PreToolUse` (Edit/Write/NotebookEdit/MultiEdit) | снять свой прошлый claim на этот файл, поставить новый через `POST /api/claims` |
| `PreToolUse` (Task) | завести `worker`, связать с родителем через `POST /api/edges` |
| `PostToolUse` (правки) | `POST /api/agents/{id}/log` — строка в ленте |
| `PostToolUse` (Task) | завершить `worker` |
| `Stop` | статус сессии → `WAITING` |
| `SessionEnd` | снять claim'ы, завершить агентов, удалить файл состояния |

Идентификатор агента — `claude-<первые 8 символов session_id>`. Идентификатор
сабагента — `sub-<sha1 от session_id + subagent_type + description>`, чтобы
`PreToolUse` и `PostToolUse` сошлись на одном узле.

## Два неочевидных места

**Claim не снимается в `PostToolUse`.** Watcher дебаунсит событие файловой
системы, поэтому diff считается уже после того, как `PostToolUse` отработал.
Если снять claim сразу, к моменту diff активных claim не останется и правка
станет `external` — ровно та ошибка, ради которой мост и писался. Claim
отваливается по `--claim-ttl` либо снимается перед следующей правкой того же
файла.

**Перед новым claim снимается предыдущий.** Мост держит файл состояния в
`$TMPDIR` только ради этого — помнить `claim_id` по каждому пути. Иначе claim'ы
на один файл копились бы до истечения TTL и засоряли список активных. На
атрибуцию это не влияет: хаб считает конфликтом только claim'ы **разных**
агентов, повторные claim одного агента схлопываются по `agent_id`.

## Ограничения

- **Правки сабагентов не отделяются от правок основной сессии.** Хуки от
  сабагентов приходят с тем же `session_id`, отдельного идентификатора в
  полезной нагрузке нет. Узел сабагента в карте появляется, но его правки
  припишутся агенту сессии.
- **Правки мимо инструментов не видны как `claimed`.** Файл, изменённый через
  `Bash` (`sed`, `>>`, `git checkout`), хуками правок не сопровождается и
  попадёт в diff как `external`. Это честно: мост не знает, что там сделал
  shell.
- **Мост никогда не роняет Claude Code.** Любая ошибка — недоступный сервер,
  таймаут, кривой ответ — гасится, код возврата всегда `0`. Если SwarmViz не
  запущен, хуки просто молчат; диагностику включает `SWARMVIZ_DEBUG=1`.
