# Мост Claude Code → SwarmViz

Claude Code ничего не сообщает SwarmViz о себе, поэтому его правки видит только
watcher — и приписывает их агенту `external`. Карта агентов при этом остаётся
пустой. Этот мост вешается на хуки Claude Code и выполняет контракт
claim-then-diff: регистрирует сессию как агента и столбит файл **до** записи,
так что diff достаётся именно ей.

## Что появляется в интерфейсе

| Виджет | Что показывает |
|---|---|
| 1 — Subagent Map | сессия как `orchestrator`, каждый вызов `Task` — дочерний `worker` со связью `TASK_DELEGATION`; на каждом узле — задача, которой агент занят прямо сейчас |
| 2 — Live Edit Stream | правки с атрибуцией `claimed` и именем агента вместо `external` |
| 3 — File Tree | счётчики правок по файлам (работало и без моста) |
| 4 — LOC Chart | дельты строк (работало и без моста) |

Сессия, запущенная в панели tmux, подписывается её координатами:
`Claude [claude:0.1]`. Идентификатор агента и так уникален
(`claude-<session_id>`), но на карте видна подпись — без панели несколько
параллельных сессий в одном репозитории выглядели бы одинаково. Панель
вытесняет имя проекта, а не дописывается к нему: узел карты узкий и режет
подпись по ширине, а внутри одного проекта имя проекта у всех сессий и так
совпадает. Вне tmux подпись прежняя, `Claude · проект`.

Под подписью на узле идёт текущая задача: для сессии — последний промпт
пользователя (хук `UserPromptSubmit`), для сабагента — промпт делегирования из
вызова `Task`. На карте видны две строки, целиком текст — в поповере по клику на
узел. Плана и рассуждений Claude Code хукам не отдаёт, поэтому формулировка
задачи ровно та, с какой её поставили.

## Установка

1. Запусти SwarmViz, перечислив все репозитории, за которыми хочешь следить, и
   увеличив TTL claim:

   ```bash
   ./swarmviz --path /путь/к/основному/репозиторию --port 8942 --claim-ttl 10s \
     --projects-root ~/projects \
     --project-paths ~/vault
   ```

   `--projects-root` подхватывает все git-репозитории прямо в каталоге,
   `--project-paths` добавляет репозитории, лежащие где-то ещё
   (через запятую). Каждый неосновной проект получает адрес `/p/{id}/...` и
   поднимается лениво — при первом обращении.

   Дефолтные `2s` для claim брать не стоит: claim ставится в `PreToolUse`, а
   diff считается уже после дебаунса (`--interval`, по умолчанию 300 мс),
   причём запись большого файла может занять заметное время. Протухший claim =
   правка уедет в `external`.

2. Скопируй блок `hooks` из `settings.example.json` в свой
   `~/.claude/settings.json` (или `.claude/settings.json` проекта), поправив
   путь к `swarmviz_hook.py`.

   Привязывать хуки к конкретному репозиторию не нужно. `~/.claude/settings.json`
   действует на **все** проекты, и мост сам разбирается, куда слать события: он
   определяет git-корень сессии, запрашивает `GET /api/projects` и выбирает
   проект с совпадающим путём (либо самый глубокий, внутри которого сессия
   лежит). Основной проект живёт на `/api/...`, остальные — на `/p/{id}/api/...`.
   Сессия в репозитории, которого SwarmViz не знает, молча игнорируется.

   Сессии в git-worktree (`.claude/worktrees/...`) сопоставляются с основным
   checkout'ом через `git rev-parse --git-common-dir`.

   `timeout` в примере — 20 секунд, и меньше ставить не стоит: первое обращение
   к лениво поднимающемуся проекту ждёт до `COLD_START_TIMEOUT` (8 с) на резолв
   и столько же на создание агента. Хук с `timeout: 5` режется ровно на холодном
   старте — то есть тогда, когда он и должен сработать.

3. Перезапусти Claude Code — хуки читаются при старте сессии.

Проверить, что мост жив:

```bash
echo '{"session_id":"test1234","cwd":"'$PWD'"}' \
  | SWARMVIZ_DEBUG=1 SWARMVIZ_URL=http://127.0.0.1:8942 \
    python3 swarmviz_hook.py session-start
curl -s localhost:8942/api/projects | python3 -m json.tool
curl -s localhost:8942/api/state | python3 -m json.tool | head -20
```

С `SWARMVIZ_DEBUG=1` в stderr будет видно, в какой проект ушло событие. В
`agents` соответствующего проекта должен появиться `claude-test1234` (для
неосновного проекта смотри `/p/{id}/api/state`).

## Настройки

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `SWARMVIZ_URL` | `http://127.0.0.1:8942` | база API |
| `SWARMVIZ_TOKEN` | — | bearer-токен, если сервер поднят с `--api-token` |
| `SWARMVIZ_REPO` | — | закрепить хуки за одним репозиторием: сессии из других молча ничего не делают. Обычно не нужно — проект определяется автоматически |
| `SWARMVIZ_DEBUG` | — | `1` — диагностика в stderr |

## Тесты

```bash
python3 -m unittest discover -s integrations/claude-code -p 'test_*.py'
```

Сопоставление сессии с проектом (точное совпадение, вложенность, worktree,
одиночный режим) покрыто тестами; сеть в них не участвует.

## Как устроено

| Хук | Действие |
|---|---|
| `SessionStart` | `POST /api/agents` — сессия как `orchestrator`, статус `RUNNING` |
| `UserPromptSubmit` | `POST /api/agents/{id}/task` — промпт пользователя как текущая задача узла |
| `PreToolUse` (Edit/Write/NotebookEdit/MultiEdit) | снять свой прошлый claim на этот файл, поставить новый через `POST /api/claims` |
| `PreToolUse` (Task) | завести `worker` с задачей из промпта делегирования, связать с родителем через `POST /api/edges` |
| `PostToolUse` (правки) | `POST /api/agents/{id}/log` — строка в ленте |
| `PostToolUse` (Task) | завершить `worker` |
| `Stop` | статус сессии → `WAITING` |
| `SessionEnd` | снять claim'ы, завершить агентов, удалить файл состояния |

Идентификатор агента — `claude-<первые 8 символов session_id>`. Идентификатор
сабагента — `sub-<sha1 от session_id + subagent_type + description>`, чтобы
`PreToolUse` и `PostToolUse` сошлись на одном узле.

## Три неочевидных места

**Claim не снимается в `PostToolUse`.** Watcher дебаунсит событие файловой
системы, поэтому diff считается уже после того, как `PostToolUse` отработал.
Если снять claim сразу, к моменту diff активных claim не останется и правка
станет `external` — ровно та ошибка, ради которой мост и писался. Claim
отваливается по `--claim-ttl` либо снимается перед следующей правкой того же
файла.

**Перед новым claim снимается предыдущий.** Мост держит файл состояния в
`$TMPDIR` только ради этого — помнить `claim_id` по каждому пути. Иначе claim'ы
на один файл копились бы до истечения TTL и засоряли список активных. На
атрибуцию это не влияет: хаб считает конфликтом только claim'ы **разных**
агентов, повторные claim одного агента схлопываются по `agent_id`.

**Агент подтверждается заново каждые 30 секунд.** Хаб держит агентов только в
памяти, так что рестарт SwarmViz стирает узел, а сессия Claude Code живёт
дальше. Если бы мост запоминал «агент создан» навсегда, до конца сессии claim'ы
уходили бы агенту, которого сервер уже не знает: правки видны, а карта пустая.
`POST /api/agents` идемпотентен (узел кладётся по `agent_id`), поэтому мост
повторяет его не чаще раза в `AGENT_REASSERT_SEC` — рестарт сервера затягивается
сам собой. Вместе с узлом восстанавливается и текущая задача: она хранится в
файле состояния сессии и уходит в теле того же запроса, иначе после рестарта
агент висел бы без подписи до следующего промпта.

## Ограничения

- **Правки сабагентов не отделяются от правок основной сессии.** Хуки от
  сабагентов приходят с тем же `session_id`, отдельного идентификатора в
  полезной нагрузке нет. Узел сабагента в карте появляется, но его правки
  припишутся агенту сессии.
- **Правки мимо инструментов не видны как `claimed`.** Файл, изменённый через
  `Bash` (`sed`, `>>`, `git checkout`), хуками правок не сопровождается и
  попадёт в diff как `external`. Это честно: мост не знает, что там сделал
  shell.
- **Мост никогда не роняет Claude Code.** Любая ошибка — недоступный сервер,
  таймаут, кривой ответ — гасится, код возврата всегда `0`. Если SwarmViz не
  запущен, хуки просто молчат; диагностику включает `SWARMVIZ_DEBUG=1`.
- **В worktree узел агента появится, а атрибуция правок — не всегда.** Сессия
  сопоставляется с основным checkout'ом, и claim ставится на путь вида
  `.claude/worktrees/x/файл`. Watcher такие пути видит, только если они не
  исключены `.gitignore` — а `.claude/worktrees/` обычно исключён.
- **Следить можно только за git-репозиториями.** Каталог без `.git` в
  `--projects-root` пропускается, а в `--project-paths` даёт ошибку старта:
  diff-движок строится на git.
